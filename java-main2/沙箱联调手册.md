# 本机后端联调 / 验收手册（沙箱环境专用）

> 这份文档解决一个具体痛点：**在这个沙箱里，后端进程活不过一条命令**，
> 导致「启动后端 → 测接口」永远失败。按下面的方式做，一次跑通。

## 1. 核心事实（先看这条，否则必踩）

| 事实 | 后果 | 对策 |
|---|---|---|
| 每条 bash 命令结束时，它拉起的子进程会被回收 | `nohup java ... &` / Python `DETACHED_PROCESS` 都留不住 | **启动后端 + 跑测试必须写进同一条命令** |
| `schtasks.exe` 在程序黑名单里 | 无法用计划任务托管 | 不要尝试，直接走「同命令」方案 |
| 系统挂了 SSL 代理 | Python 默认 urllib 请求 127.0.0.1 返回 **502**；Git Bash 的 curl 报 `os error 11001` | 用 `urllib.request.build_opener(urllib.request.ProxyHandler({}))` |
| `mvnw` / `mvn` 脚本坏、`package` 插件离线缺依赖 | 打不出 fat jar | 用 `classworlds launcher + spring-boot:run`（已封装进 `restart_backend.py`） |
| IDE 注入 `SERVER__PORT` | Spring 松散绑定成 `server.port`，端口跑到 50885 上失败 | 启动前 `env.pop("SERVER__PORT")`（脚本已处理） |
| 本机无 Chrome / Edge / Playwright | 做不了真实浏览器 E2E | 只能「接口级 + Vite 代理链路」验证，别承诺浏览器走查 |

## 2. 标准命令（复制即用）

```bash
cd "D:/workSpace/ww/java-main2/springBootTest"
PY="C:/Users/Administrator/.workbuddy/binaries/python/versions/3.13.12/python.exe"

# 一次跑完：启后端 + 接口验收（51 项）
($PY restart_backend.py 8081 >/dev/null 2>&1 &) ; $PY restart_backend.py 8081 2>/dev/null | head -1
sleep 1
$PY verify_features.py
```

需要验证「前端 → 后端」链路时（另起一个 Vite 实例，避免占用用户正在跑的 5173）：

```bash
cd "D:/workSpace/ww/java-main2/shiguang-food-login"
NODE="C:/Users/Administrator/.workbuddy/binaries/node/versions/22.22.2-2/node.exe"
nohup $NODE ./node_modules/vite/bin/vite.js --port 5174 --strictPort > /tmp/vite2.log 2>&1 &
sleep 12
"$PY" ../springBootTest/verify_via_vite.py
```

## 4. 验收脚本清单

| 脚本 | 作用 |
|---|---|
| `springBootTest/restart_backend.py [port]` | 分离进程启后端，并轮询到就绪（最多 90s） |
| `springBootTest/verify_features.py` | 五块业务功能接口验收，51 项，退出码非 0 即失败 |
| `springBootTest/verify_via_vite.py` | 经 Vite(5173/5174 → 8081) 代理验证前端实际请求链路 |

## 5. 测试数据卫生（重要）

验收脚本会写库。跑完务必清理，并**核对总数回到原值**：

```sql
DELETE oi FROM order_item oi WHERE oi.dish_name LIKE '%自测%' OR oi.dish_name LIKE '%代理链路%';
DELETE FROM orders WHERE created_at >= '2026-11-06 00:00:00';
DELETE FROM user_address WHERE name LIKE '接口自测%';
```

注意两个易错点：
- 测头像修改会把 `demo` 的 avatar 改成别的值，**记得改回 🦊**。
- `DELETE FROM orders WHERE created_at >= 今天` 会连带删掉「今天人为下的单」，
  清理前先 `SELECT` 看一眼，或按 `dish_name` 精确删。
